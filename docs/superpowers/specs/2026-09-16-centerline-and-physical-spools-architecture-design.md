# Архитектурная спецификация: Двухуровневая модель САПР (Осевая трасса и физические компоненты)

- **Дата:** 2026-09-16
- **Статус:** Согласовано
- **Область:** Доменная модель (`PipingNetwork`, `PipeSpool`), Отрисовка (`PipePainter`), Контроллер ввода и селектор (`SelectionController`, `PipingInputController`), Инспекторы свойств (`DesktopCadLayout`), Экспорт DXF (`DxfWriter`).

---

## 1. Контекст и цели

### 1.1. Проблема текущей реализации
В текущей реализации Akso понятия геометрической оси трассировки и физической катушки трубы смешаны в одной сущности `PipeSegment`:
1. **Стык «Отвод-Отвод» встык**: даже когда два смежных отвода состыкованы торцами ($L = T_1 + T_2$, физическая длина реза трубы равна 0 мм), ребро `PipeSegment` между центрами узлов сохраняется. На холсте клик в район стыка выделяет это ребро и выводит ложный бейдж длины (например, $L = 300$ мм), создавая иллюзию «неисчезающей» трубы.
2. **Арматура не разрезает трубу**: задвижки и клапаны (`Valve`) позиционируются внутри сегмента по параметрическому коэффициенту `ratio`. В результате весь сегмент трубы остается неделимым, и клик на любую часть трубы слева или справа от арматуры выделяет весь отрезок целиком. Невозможно независимо настраивать катушки до и после арматуры.
3. **Стык «Труба-Труба»**: сварные стыки на прямых трубах делили сегмент только в расчетной ведомости `SpoolCalculator`, но не делили его на интерактивном холсте.

### 1.2. Цели новой архитектуры
1. Четкое разделение на два слоя:
   - **Слой 1: Осевая трасса (Centerline)** — математический 3D-каркас направлений, уклонов, отметок уровней и привязок к строительным осям.
   - **Слой 2: Физические компоненты (Physical Components)** — реальные металлические изделия (катушки труб `PipeSpool`, арматура `Valve`, фитинги `Fitting`, монтажные стыки `WeldJoint`).
2. **Честные катушки (`PipeSpool`)**:
   - Каждая катушка трубы — самостоятельный интерактивный объект со своими 3D-границами, длиной реза, маркировкой и заводским номером.
   - Вставка арматуры или монтажного стыка «труба-труба» делит участок на независимые катушки.
   - При сопряжении отводов встык катушка трубы между ними не создается вовсе.
3. **Два режима взаимодействия**:
   - **Режим по умолчанию (Физические детали)**: клик по трубе выделяет конкретную физическую катушку.
   - **Режим «Осевая трасса» (`[ - · - ]`)**: включает видимость штрихпунктирных осей по ГОСТ, клик по оси выделяет трассу целиком для параллельного сдвига или настройки всей ветки.
4. **Каскадное редактирование длины катушки**: изменение длины катушки в инспекторе автоматически смещает последующие зависимые элементы (стыки, арматуру, отводы) по направлению оси вперед/назад с сохранением геометрии сети.

## 2. Архитектура и модель данных

### 2.1. Доменная модель `PipeSpool`
Модель `PipeSpool` переводится из категории временного результата расчета в полноценную управляемую сущность:

```dart
class PipeSpool {
  final String id;                    // Уникальный ID (напр. spool_seg1_0)
  final String segmentId;             // ID родительской трассировочной оси
  final Node3D startPoint;            // Точная 3D точка начала катушки
  final Node3D endPoint;              // Точная 3D точка конца катушки
  final double cutLengthMm;           // Фактическая строительная длина реза (мм)
  final int dn;                       // Номинальный диаметр
  final double wallThicknessMm;       // Толщина стенки
  final String material;              // Марка стали
  final String? name;                 // Маркировка / название катушки
  final String? serialNumber;         // Заводской номер / номер плавки
  final String? startJointId;         // Привязка к стыку в начале
  final String? endJointId;           // Привязка к стыку в конце
}
```

### 2.2. Правила генерации катушек (`PipingNetwork.recalculateSpools()`)
Для каждого сегмента оси `PipeSegment(startNode, endNode)`:
1. Вычисляются вычеты фитингов в узлах начала и конца ($T_{\text{start}}$, $T_{\text{end}}$).
2. Собираются все внутренние рассечения сегмента в порядке удаленности от `startNode`:
   - Монтажные стыки `WeldJoint` (включая стыки «труба-труба»).
   - Проходная арматура `Valve` (с учетом строительной длины $L$).
3. **Особый случай: сопряжение отвод-отвод встык**:
   - Если расстояние между узлами $L \le T_1 + T_2 + 1.0$ мм, катушка трубы между ними **не создается** (`spools` для данного сегмента пуст).
   - Между отводами создается ровно 1 общий сварной стык `WeldJoint` типа С17.
4. **Обычный случай с арматурой или стыками «труба-труба»**:
   - Сегмент формирует список упорядоченных катушек $S_0, S_1, \dots, S_k$.
   - Каждая катушка получает точные координаты начала и конца в 3D.
   - Пользовательские атрибуты (`name`, `serialNumber`) сохраняются по стабильным ключам катушек при пересчете геометрии.

## 3. Отрисовка на холсте (`PipePainter`) и режим «Осевая трасса»

### 3.1. Отрисовка физических катушек
- `PipePainter` выполняет рендеринг по списку активных катушек `network.spools.values`:
  - Линия катушки строится строго от `projector.project(spool.startPoint)` до `projector.project(spool.endPoint)`.
  - Если катушки нет (стык отвод-отвод), отрисовка линии трубы не производится вовсе.
  - Подсветка выбора (Highlight): подсвечивается только выбранная катушка `selectedSpoolId`.
  - Бейдж размера: выводит `L = [cutLengthMm] мм | Ду[dn]` строго для выбранной катушки.

### 3.2. Отрисовка осевой трассы (Centerline)
- В контроллер добавляется флаг `bool isCenterlineMode` (по умолчанию `false`).
- На панели инструментов (`TopBar`, `DesktopCadLayout`) размещается кнопка-тумблер `Icons.timeline` / `[ - · - Осевая трасса ]`.
- При `isCenterlineMode == true`:
  - Осевые линии между узлами трассы отрисовываются штрихпунктиром по ГОСТ 2.303-68 (тип линии осевая/центровая).
  - Узлы трассы отображаются осевыми маркерами.
  - Подсветка в режиме осевой трассы выделяет всю ось между углами.

## 4. Контроллер ввода и селектор (`SelectionController`, `PipingInputController`)

### 4.1. Логика Hit-Testing
1. **Режим по умолчанию (`isCenterlineMode == false`)**:
   - Приоритет проверки клика:
     1. Выноски (`Callout`).
     2. Арматура (`Valve`).
     3. Сварные стыки (`WeldJoint`), включая стыки «труба-труба» и «отвод-отвод».
     4. Опоры (`PipeSupport`).
     5. Фитинги/узлы (`Fitting` / `Node3D`).
     6. **Физические катушки трубы (`PipeSpool`)**: проверяется проекция на отрезок `spool.startPoint -> spool.endPoint`.
   - В результате на стыке отводов клик гарантированно выбирает стык или отвод, но не несуществующую трубу.
2. **Режим «Осевая трасса» (`isCenterlineMode == true`)**:
   - Клик по линии трубы выбирает родительский сегмент оси `selectedSegmentId`.
   - Доступен параллельный сдвиг ветки и групповое редактирование параметров трассы.

### 4.2. Каскадный сдвиг при изменении длины катушки
Метод `PipingInputController.changeSelectedSpoolLength(double newLengthMm)`:
1. Вычисляется дельта $\Delta L = \text{newLengthMm} - \text{spool.cutLengthMm}$.
2. Определяется downstream-элемент, примыкающий к концу катушки (стык «труба-труба», задвижка или узел отвода).
3. Если следующий элемент — стык или задвижка: их позиция сдвигается вперед по оси на $\Delta L$.
4. Если следующий элемент — конечный узел сегмента: конечный узел вместе со всей соединенной downstream-подсетью смещается на вектор $\Delta L \cdot \vec{u}_{\text{оси}}$.
5. Изменение записывается в историю Undo/Redo.

## 5. Инспектор свойств (`DesktopCadLayout`)

- При выборе катушки `selectedSpoolId` в правом нижнем углу отображается специализированный инспектор `_DesktopSpoolInspector`:
  - Заголовок: `Катушка трубы №... (Ду...)`
  - Поле ввода длины реза $L$ с каскадным применением.
  - Поле «Маркировка / Название».
  - Поле «Заводской № / Номер партии/плавки» (с бейджем `Ду ≥ 500` при необходимости).
  - Выбор марки стали катушки.
  - Информационный блок: толщина стенки, масса погонного метра, общая масса катушки.

---

## 6. Экспорт в AutoCAD DXF (`DxfWriter`)

- Физические катушки труб экспортируются на слой `АКСО_ТРУБЫ` (или `АКСО_КАТУШКИ`) отрезками реальной длины реза.
- Осевые линии трассы экспортируются на отдельный слой `АКСО_ОСИ_ТРАССЫ` с типом линии `DASHDOT` и тонким весом пера (0.15 мм по ГОСТ).

## 7. План верификации

1. **Модульные тесты доменной модели**:
   - Проверка генерации катушек при стыке отвод-отвод (0 катушек).
   - Проверка генерации 2 катушек при наличии задвижки.
   - Проверка генерации 2 катушек при наличии стыка «труба-труба».
   - Сохранение и слияние катушек при удалении стыка.
2. **Тесты контроллера и каскадного сдвига**:
   - Удлинение катушки смещает downstream-арматуру и отводы.
   - Проверка hit-test: клик на стык отводов выбирает стык, а не трубу.
3. **Регрессионное тестирование**:
   - Все существующие 314 тестов проекта должны выполняться без ошибок.
   - Статический анализ `dart analyze` — 0 замечаний.
